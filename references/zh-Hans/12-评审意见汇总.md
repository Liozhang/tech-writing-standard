# 12 评审意见汇总（草案 0.1）

本文件记录 12 位专家对《通用技术文档写作规范》草案 0.1 的评审结果。评审按航空防务、医疗、机械、软件四个领域，简体中文、英语、日语、韩语、阿拉伯语、希伯来语六种语言，欧洲、海湾、东亚、新兴市场等地区，以及术语本地化、结构与无障碍、标准治理三个专业视角组织。各位专家只读与其视角相关的文件，独立出具意见，未互相沟通。

## 一、总体结论

12 位专家均未给出无条件通过。4 位专家在前提条件下认可方向（软件、简体中文、结构与无障碍、机械的写作层），8 位专家判定暂不可采用。被普遍认可的部分是：分层架构、概念优先的术语库、简明语言原则、信息类型化结构。阻断点集中在五类：规则的不可执行性、领域法规符合性缺口、多语言工程缺口、无障碍未达标、规范体例不合标准起草惯例。

## 二、按主题合并的问题清单

以下按严重程度排列。P0 指阻断采用，P1 指必须修改，P2 指建议修改。问题后括注提出该问题的专家视角。

### （一）规则可执行性与自相一致

P0-1 符合性等级由组织自选，受监管文档可声明低等级以规避领域扩展和必须项，形成规避监管的通道。医疗专家还指出应规定“受监管文档强制适用完整级，等级纳入质量记录，声明后不得下调”。（医疗、治理）

P0-2 通用规则违反总纲“语言中立”原则：GEN-022 内嵌“请注意”，GEN-031 内嵌“当……时”，GEN-045 写死“您”，GEN-050 出现中文日期示例写法。示例与本地数据应下沉语言模块。（中文、治理、日韩、阿拉伯语）

P0-3 GEN-022 规定安全警示“先说后果，再说怎么做”，与 ASD-STE100 的警示规则（以明确的命令或条件开头）冲突，导致英语高安全变体必然违反通用规则。通用规则本身自相矛盾。（航空）

P0-4 英语模块普通变体的来源标注错配：句长与动词形态限制出自 ASD-STE100，却声称以微软或谷歌风格指南为基线，与“不混用两套基线”的规定矛盾；且未指定指南冲突时的仲裁人与兜底规则。（英语）

P0-5 英语高安全变体只摘录 7 条词汇规则，遗漏 ASD-STE100 的程序、描述、警告三部分写作规则及标点、从句、连接词限制；项目技术名词表的客户批准流程未规定。（航空）

P0-6 简体中文模块 ZH-010 定为“必须”但句长无计数定义（标点、数字、西文是否计入、句子如何切分均未写）；中文模块的参数表缺时间格式、货币、姓名顺序、地址、电话、排序、礼貌层级、定名机构、译文长度余量九项必填参数，形式未完成，不能用于完整级。（中文）

P0-7 语言模块编写指南的必含清单与参数表缺失日语、韩语核心要素（敬体常体与敬语规则、汉字假名混排与禁则、注音与振り仮名、纵排、计数词与读法）；“文字方向”一节为散文表述，无规则编号与级别，无法接入流水线门禁；且遗漏表格列序、嵌套列表缩进、代码块方向隔离、图示箭头与方位词等从右向左读者的核心对象。（日韩、阿拉伯语）

P0-8 术语库与翻译交接的非强制化：术语基线与黑名单交付为“应该”，供应商拿不到强制基线；占位符与标记完整性检查为“应该”且未覆盖结构化标记、变量、代码与不译项，导致“先提案后使用”的流程无法运行。（术语本地化）

P0-9 信息类型只有概念、操作、参考三类，不设教程与排障两类，开发者文档的快速上手与常见问题无处安放，与业界通行的四分类冲突；DITA 与简化 Markdown 两条路径之间没有迁移边界。（软件、结构与无障碍）

P0-10 工具链未规定检查范围排除代码块与行内代码，全半角、句长、拼写检查会对命令、标识符、程序输出大量误报，中文文档尤甚。（软件）

P0-11 四个领域扩展均无可执行的内容清单与法规锚点：航空缺适用性机制与构型清单管理；医疗缺说明书法定内容清单、物质形态要求、使用相关风险分析与文件控制要求；机械缺法定内容清单（噪音振动数据、残存风险、报废处置、备件识别、培训资质、个人防护装备）；软件缺接口参考、错误码表、示例许可、双界面权威与多版本规则。（航空、医疗、机械、软件）

P0-12 全套规则默认读者具备文字读写能力与稳定的网络电源条件，低识字率、低带宽、离线、黑白印刷场景完全没有出现，“所有地区”的定位与实际覆盖不符。（新兴市场）

P1-1 总纲称四项原则“不得违背”，冲突裁决顺序却把上位原则排在末位，自相矛盾；应把原则列首位。（治理）

P1-2 规则元数据一处称五项要素、一处称六字段，且多数规则只写理由不写来源，要素实际不可见；应统一字段并在每条规则下完整展示。（治理）

P1-3 工具链检查项标为“必须”，导语却写“建议接入”；应改为“完整级必须接入，其余等级可裁剪”。（治理）

P1-4 GEN-050 定“以本地格式为解释对象”，ZH-031 定“以数字格式为准”，同一规范两个权威，日期误读有实际风险，须统一口径。（中文）

P1-5 多处规则不可验证：GEN-030“同一肌肉记忆”无判定标准（航空、软件、英语均指出）；GEN-044“尽量具体”、GEN-046“避免幽默”无可观察判据；应改为可检验表述。（多视角）

P1-6 三档级别之外散见“禁止”“须”“尽量、建议”等未映射强度的用词，约束力不可判定；按标准起草惯例宜只保留三档并逐一归并。（治理、结构）

P1-7 GEN-034 以“听到什么提示”作为完成判据，与无障碍的传感特征要求冲突，须同时含视觉或文字判据；GEN-061 未区分装饰性图示，会产生读屏噪音。（结构与无障碍）

### （二）语言层

P1-8 简体中文模块与国标和工程实践的冲突：书名号涵盖文件名与软件文档惯例冲突（应限标准与著作，文件名与界面元素另行规定）；ZH-024“标点一律全角”与参数表千分位用半角逗号矛盾，且未注明四位数以下不分节；ZH-013 一律避免“被”字句过绝对，描述不可控系统事件时被动更准确；三种连接号无用法对应，缺标题句末、列表项、顿号分号规则；ZH-023 引用社区指南定“必须”缺国标依据。中文专家的总体判断是可有条件采用。（中文）

P1-9 英语模块：英式拼写应作地域参数而非另设语言模块；EN-102“多词名词不超过三个词”疑非 ASD-STE100 原文规则，航空复合名词常超三词，须核对或降级；EN-001 缺计数法（连字符词、缩写、标题是否计入），工具无法自动检查；EN-009 与 GEN-046 重复，两层同款必然漂移。（英语）

P1-10 日语、韩语：须给出句长上限的确定方法（抽取母语真实译文测量、取分位数、母语评审、目标地区理解度测试、登记记录），可给参考初值但注明须实测替换；术语库缺各语言读音、同形异义标记、地区禁用字段，大数字读法（万、亿进位差异）与计数词无对应机制；CLDR 不覆盖敬语、礼貌层级、纵排，不能替代母语审定；译文扩张比例三成对界面文本不成立，应按模块实测并设上下限。（日韩）

P1-11 阿拉伯语、希伯来语：STR-043 应升为必须并定义校对范围与责任人；缺历法参数（沙特等国官方文书用伊斯兰历，只承认格里历不符合当地法规）与数字系统参数（阿拉伯-印度数字在海湾通用，须规定同一文档集只用一种）；术语首现的拉丁转写规则缺失；工具链缺双向文本渲染检查。（阿拉伯语）

### （三）领域层

P1-12 航空防务：补图解符号体系来源（客户符号标准、ISO 7000、IEC 60417）与符号变更走构型变更；补实际构型与文档不符的处置（构型控制责任方、偏离申请客户签批、临时件发布）；补非英语技术出版物的处置；警示分级与本领域惯例（危险、警告、注意、提示四级）映射；总纲裁决链未含合同及客户引用规范，应置于链首并规定书面偏离流程。（航空）

P1-13 医疗：说明书内容清单须对应欧盟医疗器械法规附件一第 23.1 条、体外诊断法规附件一第 20.2 条、美国 21 CFR 801.18 与中国《医疗器械说明书和标签管理规定》；语言清单按目标市场法规确定而非绝对化“不得只提供英语”；补随器械提供的物质形态要求（欧盟法规第 10 条第 7 款）与医疗器械唯一标识；安全警示结构与警示标志、信号词句式（信号词、危险源、后果、措施）对应；补使用相关风险分析与可用性验证要求（IEC 62366-1）；文件控制按 ISO 13485 与 21 CFR 820.40 补齐批准人、变更原因、电子签名与归档期限；补上市后信息变更的告知义务。（医疗）

P1-14 机械：补法定内容清单表（噪音与振动排放值依欧盟机械法规 (EU) 2023/1230 附件三、预期用途与可合理预见误用依 ISO 12100、残存风险清单、报废处置、备件识别、培训资质、个人防护装备）；安全标志锚定 ISO 3864、ISO 7010、IEC 60417；补能量隔离条款（锁定挂牌、多人协同、起吊搬运、高处作业），这是机械事故最高发环节；维护周期表与扭矩表、润滑表、磨损极限、故障代码表、专用工具清单升为必须；补维修手册与备件册的专门结构（零件分解图与件号对应、分册规则、改装套件构型变更、维保记录表）；多语言要求须配市场语言矩阵模板与漏配门禁。（机械）

P1-15 软件：接口参考须由源码注释或接口描述文件单一来源生成并做流水线一致性校验；错误码表与工具输出同源，排障内容含日志采集与自检命令；示例代码带许可声明并注明第三方来源；命令行与图形界面并存时明确权威方；多版本文档并存时默认指向稳定版、无版本号地址重定向、页面标明适用版本、弃用给公告期与迁移说明；区分预览环境发布与正式发布；“文档即代码”各要求从“应该”升为软件领域必须项。（软件）

### （四）多语言工程

P1-16 术语库数据模型缺地区变体代码、词形级作废状态；搭配与大小写规则应升为必须；术语变更影响清单应升为必须并接入流水线强制回改；缺存量文档迁移路径、条目定期复审与覆盖率指标；翻译交接包须成型（上下文与截图、字数与格式、问题上报、验收与退回标准）；多语言版本同步缺时限、翻译滞后处理与译中单元锁定；术语库须有读音字段供朗读与合成。（术语本地化、日韩）

P1-17 引用机制与复用：未定义引用语法、目标唯一性与循环禁止，也无校验手段；缺引用完整性与近似重复内容检查；信息单元无粒度判据（一个单元回答一个读者任务为上限）；STR-051“地域差异单独成单元”与单一内容源冲突，应区分条件差异（用条件属性在单元内标注、按地区过滤发布）与内容差异。图文分离须落到工程机制（保留文本层的图示格式、图中文字进翻译包、禁止正文必需文字做成纯位图）；译文扩张须落到模板（禁固定高度容器与绝对定位、规定字符串上限与截断策略）。（结构与无障碍、术语本地化）

P1-18 无障碍远未达到网页内容无障碍指南 AA 级实质要求：缺语言属性（读屏无法在多语言混排中切换语音）、时基媒体替代、键盘可达、阅读顺序、复杂表格拆解、非文本对比；“缩放至两倍”低于 AA 要求的 400% 或视口宽 320 像素；对比度未给数值（正文 4.5:1，大字 3:1）；可打印版须输出带标签 PDF 或提供等效网页路径；不得对外声明符合 AA 级。（结构与无障碍）

P1-19 图形优先不成体系：图示步骤号未要求与正文步骤号一一对应；符号一致性未纳入术语库（术语库只管文字词条）；未规定纯图示版本的发布与验收；图形优先与符号替代仅限航空领域且为“应该”，应升为通用必须项并覆盖机械、医疗。（新兴市场、结构）

P1-20 小语种与社区路径缺失：语言模块规划未含斯瓦希里语、豪萨语、印地语、孟加拉语、他加禄语等新兴市场语言；CLDR 对小语种不全须允许社区补录；缺社区翻译流程与配合现场培训的口述讲解脚本；译员能力认定在资源受限地区不可得，须给替代认定方式。（新兴市场）

P1-21 理解度测试样本未按识字水平、年龄、使用经验分层；未规定测试失败后的复测与放行门槛；低识字读者应允许口头回答或现场操作演示替代书面复述。（新兴市场、医疗）

### （五）治理体例

P1-22 缺标准体例要素：前言、规范性引用文件、术语和定义、索引；章节未按标准条款编号；未区分注日期与不注日期引用（宜统一不注日期并声明以最新版本为准，核对义务由维护组承担而非压给使用者）；符合性声明模板未载语言模块与领域扩展版本号，与模块独立版本叠加后认证对象不可确定；缺符合性评定程序（检验规则、抽样方法、不符合分级、豁免审批记录、证书管理）；复审缺机构与结论处理规定；未采用标准名录宜标注为资料性附录。（治理）

## 三、各视角整体结论一览

| 视角 | 结论 |
|---|---|
| 航空防务 | 暂不能采用；安全警示用语惯例与适用性信息两类合同强制要素有实质缺口 |
| 医疗 | 暂不适用；缺法规强制的内容清单、语言依据、物质形态、上市后告知与文件控制 |
| 机械 | 写作层成熟可采纳；领域扩展只是提示性附录，缺能量隔离等底线条款 |
| 软件 | 可采纳，但须先扩展信息类型、隔离代码检查范围并补齐四类条款 |
| 简体中文 | 可有条件采用；须完成 2 项 P0 与 6 项 P1 后试跑真实文档 |
| 英语 | 不能直接采用；普通变体的来源标注、指南仲裁、地域参数三项须先解决 |
| 日语、韩语 | 暂不可采用；框架可按适配级先行，完整级前须补齐必含清单与句长方法 |
| 阿拉伯语、希伯来语 | 方向性问题只需补条款；补齐后可至审核级，完整级须先解决 P0 |
| 术语与本地化 | 原则层到位，流程层“拿不到、查不出、退不回”，不可真正运行 |
| 结构与无障碍 | 骨架方向正确；无障碍暂不能对外声明符合 AA 级 |
| 标准治理 | 暂不具备第三方认证条件，宜定位为组织内部试用稿 |
| 新兴市场 | 暂不可用；缺口在默认读者具备读写能力与数字访问条件 |

## 四、修订批次建议

第一批（消除 P0）：修正 GEN-022 警示顺序；把通用规则中的中文示例与本地数据下沉语言模块；统一逻辑矛盾的条款（GEN-050 与 ZH-031、元数据字段、检查项导语、原则与裁决顺序）；补中文句长计数定义与参数表九项；补日韩与从右向左的必含要素并给文字方向一节加编号；术语基线与占位符检查升为必须；信息类型加教程与排障两类；规定检查范围排除代码域；四个领域扩展补法定内容清单；总纲增补低识字读者适配原则。

第二批（消除 P1）：按本报告第三节逐条修订语言模块、领域扩展、术语库、无障碍与治理体例。

第三批（验证）：用真实合同样例做端到端符合性演练，用真实文档试跑工具链度量，用 2 至 3 篇真实文档按语言分别做理解度测试，再升版。
