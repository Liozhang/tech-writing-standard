写完文档再检查，输出分必须违反、应该违反、待人工复核三类的修订清单。规则可
逐条追溯到国际标准。规范能证明什么，就写什么：已承诺的、已有证据的、仍然开
放的，三者分开写。

- 英文主说明见 [README.md](README.md)，技能英文入口见
  [SKILL.md](SKILL.md)。

## 为什么做这件事

三个近期公开事实推动了这个项目。每一件都改变了写作规范必须承担的责任。

**一、人工智能生成内容变成监管对象。** 欧盟人工智能法案第 50 条透明度义
务自 2026 年 8 月 2 日起适用。人工智能生成或加工的内容须可识别，聊天机器
人交互须告知，合成媒体须标注。技术文档越来越多由语言模型起草。监管方有权
要求你识别的内容，不能是来源与修订记录无人跟踪的内容。因此本规范把来源可
追溯与版本管理定为必须项，不当作良好习惯。

**二、代码产出速度超过文档质量。** 使用人工智能编程工具的团队报告了可观
的产出提升，部分实测的提速最高达五成五。2026 年开发者工具链的评论文章反
复提醒同一件事：人工智能会产出错误假设、过时做法和看似合理实则错误的细
节。代码在加速，解释代码的手册要么没写，要么同样未经审校由机器起草。本规
范的应对是把规则做成可机检，让文档可测量，而不只是可阅读。

**三、机器生成的文字需要可机检的规则。** CodeRabbit 2025 年 12 月对人工
智能与人工生成代码的对比分析发现，人工智能生成的代码波动更大，更容易引
入高严重程度的问题。同一机理适用于文字：流畅不等于准确。一套规则若无法被
检查，只会产出看起来合规的文档。所以本仓库的设计原则是：规则只要重要，就
必须有编号、级别、检查方式和豁免路径。

**四、自然语言成了编程语言。** 2025 年 2 月 Andrej Karpathy 提出"氛围编
程"，描述人用自然语言表达意图、由机器写代码的工作方式。他那句"最热门的新
编程语言是英语"如今被当作对人工智能时代的预言频繁引用。2025 年 12 月底他
又写道，作为一名程序员，他从未感到如此落后。当自然语言是代码生成的输入，
文字质量就是构建依赖。一套让文字不被测量的规范，等于放任工具链的主要输入
不受控。

**五、机器写的文字正在失去人的痕迹。** 2026 年 7 月一篇发布于 arXiv 的探索
性研究以检测开发者代码与注释中哪些出自大语言模型为题，其前提是这类输出
带有可辨识的特征。注释质量本来是长期弱项；2026 年一份分析测得，等价的文
档字符串能让大语言模型对函数输出的预测准确率提高 12.8% 至 24.5%。所以文
档不是代码的副产品，而是一种改变人与机器理解代码效果的输入。这就是本仓库
把它当作按规范撰写并加以测量的对象的原因。

**六、受控语言变成了提示词，而提示词没有词典。** 2026 年 10 月 2 日 Andrej
Karpathy 发帖说，他会要求语言模型按 ASD-STE100 讲解主题。那是为航空维护手
册制定的受控英语。他反映，该标准对清晰写作风格的强约束，产出的文字可读性
高得多。因为标准很严，他有时只要"ASD-STE100 的百分之八十"。

这个想法此前已在开发者社区传开。多个开源技能把 STE 规则用到智能体阅读的
文本上。

两项局限已有记录。该标准建在约 900 个批准词的词典上。语言模型没有这本词
典，得到的是 STE 风味的英语，不是 STE。严格还会用内容换简短。2026 年 8 月
一次小实验中，宽松指令把 Claude 的平均句长从约 18 词降到 9 到 10 词，同时
丢失 8.5% 的代码专属事实；完整指令丢失 46.8%。

受控语言要可用，需要三样东西：词表、可检查的规则、可部分应用的方式。
ASD-STE100 只覆盖英语。本仓库为两种语言把这三样都建了出来。

## 仓库里有什么

| 部分 | 作用 |
|---|---|
| 通用规则 | 73 条语言中立规则，GEN-001 至 GEN-073 |
| 语言模块 | 简体中文 ZH-001 至 ZH-027，英语 EN-001 至 EN-107，含高安全变体 |
| 领域扩展 | 航空防务、医疗、机械、软件 |
| 结构与交付 | 信息结构、元数据、版本、发布、无障碍、受限交付 STR-001 至 STR-053 |
| 术语库规则 | 概念优先的多语言术语管理 TERM-001 至 TERM-040 |
| 工具链规则 | 自动检查与理解度测试 TOOL-001 至 TOOL-072 |
| 门禁脚本 | 四种模式：中文句长、英语句长、无障碍、术语一致性 |
| 完整示例 | 按本规范写成的生物信息流水线操作指南及配套术语库 |

## 作为技能安装

```bash
cp -r tech-writing-standard ~/.zcode/skills/
```

`SKILL.md` 是英文入口，`SKILL.zh-CN.md` 是中文入口。技能系统默认加载
`SKILL.md`；要用中文工作，在安装后的目录里把 `SKILL.zh-CN.md` 复制为
`SKILL.md`。

## 单独使用门禁脚本

脚本只依赖 Python 3，不需要第三方包。

```bash
python scripts/doccheck.py <文件或目录> 50        # 中文句长、混排、标题、规则级别
python scripts/doccheck.py <文件或目录> --en      # 英语句超 25 词
python scripts/doccheck.py <文件或目录> --a11y    # 无障碍可机检项
python scripts/doccheck.py <文件或目录> --term    # 禁用词与同义混用
python scripts/doccheck.py <文件或目录> --term --termbase <术语库.csv>
```

单元测试：

```bash
python scripts/test_doccheck.py
```

1.2 版为 27 项，全部通过。

## 双语策略

技能与规则摘要以英文为主。简体中文模块的权威文本保留中文，因为 ZH 规则规
定中文的计字方法与标点引号惯例，翻译后失真。两个入口实现同一套流程与同一
组命令。两边对规则内容的表述不一致时，以 `references/zh-Hans/` 的中文文本
为准，并应把不一致当缺陷上报。

## 符合性等级

| 等级 | 要求 |
|---|---|
| 完整级 | 全部必须项加领域扩展，另加真人理解度测试、读屏实测、双人审校 |
| 审核级 | 全部必须项，应该项可经评审豁免 |
| 适配级 | 全部必须项，可以项自行取舍 |

完整级未开放。真人理解度测试、读屏实测、术语项目验证、译文余量实测、资源
受限阈值实测五项未完成，任何文档不得声明完整级。

## 公开局限

- 门禁脚本只覆盖可机检子集。语义完整性、操作顺序正确性、安全充分性必须人工审校。
- 脚本面向散文类文本。代码、命令、路径与机器生成输出按规则排除。
- 表格行按版面结构统计，不计入句长违规。
- 简体中文句长上限来自专家评审与 326 句语料的分位数测量。真人理解度测试未做，该组数值是参考值，不是认证值。
- 模拟读者与语言模型不能作为需要真人关口的证据。

## 规则的成文过程

规范先汇总现有写作标准，再经过四轮留档的外部评审：12 位领域语言区域专家、
7 位母语专家复核、10 位科研领域专家，以及 26 位专家关于 1.0 版能诚实承诺
什么的讨论。全部记录随仓库分发在 `references/zh-Hans/`，其中包括记录规范
自身违反自身规则的那些文件。
